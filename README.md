# qingxiao-chronicles

青霄纪

## 青霄论道

根据《修仙游戏属性与战斗系统设计方案.md》实现的网页版单人斗法原型。

## 运行

无需安装依赖，在本目录运行：

```sh
python3 -m http.server 8000 --directory dist
```

浏览器访问 `http://localhost:8000`。页面使用 ES modules，应通过 HTTP 服务打开。

## 已实现

- 火木法修、太玄剑修各 8 个神通，开战前从本派装备 6 个；通用行动和应对不占槽位。
- 每派有两个主修方向，效果与基础心法同时生效：引燃爆发 / 生息消耗、快剑压制 / 藏锋重剑。
- 配装界面支持查看主修规则、神通费用与距离、一键推荐、槽位校验。打开时暂停战斗，取消沿用原局，应用后开启新局；重新论道保留当前配置。
- 每回合 3 行动点、5 点纳气、10 点灵气容量，灵气跨回合保留。
- 近、中、远三档距离，以及固定预告的敌方招式计划；神通卡标明有效距离与当前是否超距。距离只限制技能有效范围，不直接改变伤害。追风剑只适合近身，普通剑招和其他打断技适合近中距，蓄势大招适合中远距且释放时检查距离，焚炎术仅近中距有效；催生术、流火诀、星火引仍可远距使用，自身恢复、防守不限距离。
- 血条、状态、人物和场内文字各有独立空间，状态增加时自动撑开布局，兼容手机与桌面。
- 灵种、灼烧、剑意、破绽、护盾、蓄势与打断。蓄势后仍可使用剩余行动移动、调息或施展已装备的防守招式，其他神通锁定；下次行动开始免费释放，费用与伤害不变。
- 每回合一次手动应对窗口，敌人也有按资源限制的应对。
- 通用基础攻击、移动、调息与净息。
- 战斗记录、技能费用与伤害预估、指南、胜负结算、重新开始。
- 本场斗法纪要完整保留，无条数上限；向上翻阅旧记录时不自动跳到最新，重新论道或切换流派时清空。
- 自动斗法支持均衡、强攻、稳守、蓄势四种倾向及三档出招节奏，可随时暂停转手动；出招、应对与选择理由均写入纪要。
- 桌面与移动端布局，以及支持浏览器中的 WebMCP 状态读取和行动接口。
- 两种流派对局中的双方立绘受击均保持朝向并轻微位移；支持系统减少动态效果设置。

## 原型取舍

- 固定玩家先手，不实现先手属性争夺。
- 同境切磋，气血耗尽即认输，不实现寿元与永久伤势。
- 不实现法宝装备与词条编辑、成长养成、存档、多人联机与更多流派。
- 灵气超过容量时按功法生成顺序接收至容量上限，剩余溢出；暂未实现自选保留顺序。
- 灼烧在目标行动阶段开始时结算，持续 3 次，穿过护盾；护盾跨回合保留，上限 60。
- 任意灵气费用优先消耗通灵，再消耗当前数量最多的属性。

## 文件

- `dist/index.html`：页面结构。
- `dist/style.css`：界面与响应式布局。
- `dist/engine.mjs`：独立战斗规则与敌方计划。
- `dist/loadout.mjs`：主修与神通配装界面、草稿配置和推荐搭配。
- `dist/auto.mjs`：自动战斗规划与应对策略，四种倾向使用不同的攻防与铺垫权重。
- `dist/app.mjs`：页面交互、动画与战斗流程。
- `dist/assets/`：斗法场景与角色美术。

## 平衡性测试

```sh
node test-balance-harness.mjs
node scripts/balance-heal.mjs
node scripts/balance-heal.mjs --expand heal18
node scripts/balance-heal-report.mjs
```

本轮约需 7 分钟。先独立筛选回春 26 / 22 / 18 恢复，以及恢复 26 但只清 2 层灼烧，核对 144 个基准场景；随后为采用的 18 点档补齐配装。实际执行 2232 场完整对局与 96 个有限灼烧片段。采用值矩阵包含 1824 个场景，其中复用已测采用值 432 个、未装备回春且规则不可触发的基准场景 216 个；这些不算新增独立对局。每档引擎相互隔离，自动模拟采用对应数值，控制器内容保持不变。

回春采用基础恢复 18，全清灼烧不变。生息推荐配置的全距离胜出占比从 79.7% 降至 75.0%，中距从 79.7% 降至 71.9%，远距仍为 84.4%。引燃全距离从 59.9% 降至 53.1%。对剑修自选配装的生息占比仍为 91.7%，后续优先复查射程、移动行动与 AI 预测，避免继续叠加恢复削弱。结果为确定性场景占比，不是真人胜率。

当前剑修没有施加灼烧的技能，单独削弱回春清灼烧不会直接改变火木对剑修对局；清除候选的交叉结果按结构性结论复用，另外实际测试了火木镜像与灼烧片段。

旧数据保留在 `docs/balance/`、`docs/balance/charge-window/`、`docs/balance/sustain-recovery/`；本轮在 `docs/balance/heal-recovery/`。上面的命令复现本轮；旧生成器应在对应历史源提交运行，避免以当前规则覆盖旧数据。通用矩阵可用 `node scripts/balance.mjs --out docs/balance/自选新目录` 输出到新目录。线上仍固定玩家先手，敌方执行公开预告。

## 射程与接近成本修订

本轮仅将焚炎术从全距离改为近身 / 中距；伤害、费用、回血与线上自动控制器保持不变。催生术、流火诀、星火引仍支持远距，离火焚天仍限中远距；剑修接近不返还行动。技能卡、配装与指南同步标明有效范围。

测试比较现行规则、低耗火法限距、普通火法整体限距、剑修首次接近返还，以及追加的单张焚炎限距。实际共 3490 次对局执行（含延长重跑和时限未决），采用值完整矩阵 1824 个情境，无 30 回合未决。推荐配置生息全距离胜出占比 75.0%→62.5%，中距 71.9%→54.7%，远距 84.4%→68.8%；引燃远距 71.9%→51.6%。这是确定性自动对局占比，不是真人胜率。

不同配装与控制器并非全部同向变化；生息自选配装占比反而从 41.1% 增至 45.5%。额外的即时回合控制器与公开脚本预测比较显示结果明显依赖行动评分方式；实验控制器未上线。下一轮先复查预测误差，再独立验证枯荣周转与先手。详见 [射程与接近成本修订对照](docs/射程与接近成本修订对照.md)。

```sh
node scripts/balance-range.mjs
node scripts/balance-range.mjs --long
node scripts/balance-range.mjs --expand blaze_mid
node scripts/balance-range.mjs --diagnose low_mid
node scripts/balance-range.mjs --diagnose blaze_mid
node scripts/balance-range-report.mjs
```

本轮生成器读取 `docs/balance/range-movement/source.json.gz` 中冻结的引擎、控制器与擂台源文件，采用值更改后仍可复现同一基准。旧数值实验请使用各自历史源文件或提交，不覆盖历史数据。

## 离线双 AI 有限层预测

新增独立实验擂台，明确处理先后手、跨回合纳气、阶段灼烧和免费蓄势释放；自己的组合试算与未来预测都使用实际双 AI 的应对规则。有限层预测会按对手控制器重新选招，达到深度上限时用即时评分近似，避免相互无限递归；每次最多对 12 个己方组合预测敌方阶段，预留蓄势、恢复、移动等战术候选。旧擂台、历史数据和线上自动控制器保留。

```sh
node test-predictive-arena.mjs
node scripts/balance-prediction.mjs --out /tmp/qingxiao-adaptive-prediction
node scripts/prediction-report.mjs /tmp/qingxiao-adaptive-prediction
```

本轮比较旧控制器、即时评分、统一时序的脚本预测和有限层重新决策，使用推荐配装与双方均衡倾向。每种控制器覆盖 24 个跨派场景和 24 个镜像场景，共保留 192 次对局对照；阶段预测在同一实际对局中采样，不计作新增独立对局。另有未限制候选数的先导批次中止，未纳入对照。结果与限制见 [离线双 AI 有限层预测对照](docs/离线双AI有限层预测对照.md)，原始数据在 `docs/balance/adaptive-prediction/`。

新擂台在 24 个跨派场景中复现了旧控制器的结果、动作和应对次数；另验证完整状态重放、双方应对的搜索副本、深度上限、先后手边界、不可变性与人物身份交换。已知算法的准确重放是规则检查，不能等同于最优打法；有限层控制器之间仍可能因截断产生误差。实验暂未接入网页，也未调整技能数值。
